# v0.8.0 — OpenCode joins the ensemble

Awaitonal now supports **OpenCode 1.18.33 (V1)** alongside Claude Code, Codex,
and Pi. The native plugin sends final assistant prose to the existing local
service for classification and sound synthesis. All four integrations share
the warm service, palette, session voices, and global mute.

- Completed replies use the existing musical gestures and timing variations.
- Permission requests and questions play the corresponding attention cues.
- Terminal errors produce a generic failure cue without forwarding error details.
- Cancelled or uncertain results and child sessions stay quiet. Retry and
  compaction boundaries prevent earlier prose from becoming a final notification.

Only bounded final assistant text and lifecycle identifiers cross the local
bridge. Prompts, reasoning, tool output, permission patterns, and question text
are excluded. Notification events never install dependencies or start the service.
This release adds no new musical arrangements or classifier changes.

## Set up OpenCode

With OpenCode 1.18.33, Python 3.11+, and uv available:

```sh
git clone --branch v0.8.0 --depth 1 https://github.com/sindarknave/awaitonal.git
cd awaitonal
sh scripts/plugin-runtime.sh setup --adapter opencode
```

Add the file URL for `extensions/opencode.ts` to your existing OpenCode `plugin`
list, preserving other entries, then restart OpenCode:

```json
{
  "plugin": ["file:///absolute/path/to/awaitonal/extensions/opencode.ts"]
}
```

Keep the checkout available. Setup installs the shared Python runtime separately;
it does not edit OpenCode settings. Use the same script with `status`, `mute`, or
`unmute` to control the service. See the
[OpenCode guide](https://github.com/sindarknave/awaitonal/blob/v0.8.0/docs/opencode.md)
for file URLs with spaces, standalone installations, diagnostics, and removal.

## Update existing integrations

Update the Claude plugin and rerun `/awaitonal:setup`, or update the Codex plugin
and rerun its setup skill. For Pi, install the new tag, reload, and run
`/awaitonal-setup`:

```sh
pi install git:github.com/sindarknave/awaitonal@v0.8.0
```

For an existing OpenCode checkout, update its files, rerun setup with
`--adapter opencode`, and restart OpenCode. Updating plugin files alone does not
upgrade the running Python service. Setup remains an explicit local action.

## Validation and limits

The full local Python suite passes 2,259 tests with two optional-model skips.
All 23 Pi extension tests pass. After the version bump, another 149 packaging,
setup, lifecycle, diagnostics, and CLI checks pass with one optional-model skip.

All 25 OpenCode bridge tests pass, along with a strict typecheck against the
1.18.33 plugin and SDK. Pre-release checks loaded the plugin in the actual native
OpenCode runtime and ran ten synthetic scenarios through an installed wheel,
private socket, resident rules service, and WAV renderer. Six expected WAVs were
produced; cancellation, child sessions, and mute stayed quiet. Real session
creation, parent/child identity, and empty-session aborts were also checked.

No live model turn, real TUI permission interaction, or audio-device playback was
tested. Support is limited to the verified **V1 1.18.33** lifecycle; OpenCode V2
uses a different API. Audio playback remains macOS-only. Missing timing uses
ordinary cues, and already-forwarded attention cannot be recalled until turn
settlement. See the
[validation record](https://github.com/sindarknave/awaitonal/blob/v0.8.0/VALIDATION.md)
for build provenance and the broader regression checks.

Downloads include the Python wheel, source archive, plugin package tarball,
offline listening preview, and SHA-256 checksums. The preview is unchanged from
v0.7.0 and remains available for hearing the current musical palette.

This remains a prerelease, consistent with previous versions.
