# Awaitonal 0.2.0

The auditioned result and handoff palette is now used by the live notification
service. Changes, answers, plans, artifacts, publication, choices, required
actions, and caveats have distinct cues. Direct review invitations use a softer
expectant cue; sign-in and approval requests use the stronger waiting cue. The
original refusal sound remains available.

- Classification adds delivery, expectancy, handoff, and selected-gesture metadata.
  The original four outcome states and hook wire format remain compatible.
- The service plays the selected gesture. Review invitations keep routine queue
  priority; required actions and choices retain attention priority.
- Rules distinguish current requests from examples, optional offers, and resolved
  dependencies. Both backends use shared explicit routing; optional MiniLM remains
  an experimental four-outcome fallback.
- The evaluator can score gesture, expectancy, and delivery labels independently.
  New fixtures are synthetic development contrasts, not a held-out accuracy claim.
- Hooks now verify the local socket endpoint and connected peer before sending
  assistant text, closing the local-user impersonation issue found in the audit.
  This release also includes the earlier long-input parsing reliability fix.

Run `awaitonal demo` to hear the complete palette, or `awaitonal play review` and
`awaitonal play needs-you` to compare the two expectant cues. Restart an already
running service after upgrading. Existing palette overrides merge with the new
defaults; old event arrays keep their customized sound.

See [routing details](../gesture-routing.md) and [observed validation](../../VALIDATION.md).
Installation does not modify Claude settings or install a background service.
